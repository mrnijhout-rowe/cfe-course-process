# COURSE.md - CS4120 Course Facts

Facts about the course as it is. Tags follow CLAUDE.md section 1.
Revised 2026-09-27 at the start of the second build, and 2026-10-05
when Dan approved the course structure.

## Catalog

- **[RULE]** Official description: introduction to basic programming
  skills and Python 3. Topics: variables, expressions and statements,
  functions, conditionals, loops, recursion, string manipulation,
  input/output, lists, dictionaries. Applications drawn from
  mathematics, science, engineering, and the humanities.
- **[RULE]** Audience: students with no prior CS coursework. Assume zero
  programming experience and high general academic ability. Some
  students chose this course because it is not the intensive track;
  respect that. Two fall sections run in parallel and must pace
  identically.

## Meetings and calendar

- **[RULE]** Four meetings per week: three 50-minute classes and one
  90-minute class, on a rotating letter-day timetable, so nothing is
  tied to a weekday. Plans are written in 50-minute lessons.
- Week grids and key dates: CALENDAR_MAP.md. Fall 2026 runs Aug 18 to
  Dec 7; Fall Break is Oct 5 to 9; Thanksgiving is Nov 23 to 27. The
  final-exam period is not used.
- **[RULE]** The last ~12 meetings are reserved: ~6 speed run, ~6 final
  project.

## Sources

- **Unit 1:** the department's reading series (R1 to R4), in the
  first-build repository. Done.
- **Coding units:** Think Python, 3rd edition, by Allen Downey. Every
  student has the print book; the chapter notebooks are in
  sources/thinkpython/ as raw material for examples and exercises.
  Think Python is source, not syllabus: each unit plan says which
  chapters and which topics are in.
- **Exercises and labs:** Codio's built-in course "Python Programming
  from Codio," imported per topic into the course's Codio class.
- **Peer instruction questions:** sources/peer_instruction/, the bank for
  the Plickers concept checks that CLAUDE.md section 2 makes a default.

## Platform

- **[RULE]** Codio is the assignment platform. Homework is traditional
  Codio guides with .py files and autograders. No Jupyter notebooks in
  this build.
- Canvas carries the course page. Each coding lesson has a Canvas page,
  written here (CLAUDE.md section 6) and pasted in by Dan before class,
  with a unit page at the top of each unit and a project page for each
  project. Due dates live only in Canvas and Codio, never on the pages.
- Reading quizzes are Codio multiple-choice assessments. Unit quizzes
  are taken in Canvas.
- **[RULE]** The course Gemini Gem is the sanctioned AI tutor, allowed on
  every assignment all semester. Its prompt is Dan's; it is not authored
  here. It answers syntax questions directly, turns problem-solving
  questions back into questions, and does not write assignments.
- Students keep paper journals. Learning checks are answered in the
  journals, which Dan collects.

## Grading

| Category | Weight |
|---|---|
| Projects | 25% |
| Tests and quizzes | 25% |
| Labs/Learning Checks | 35% |
| Final project | 15% |

- Labs/Learning Checks holds Codio work, problem sets, labs, and
  learning checks. Reading quizzes and unit quizzes fall under Tests
  and quizzes. Unit projects and larger mini-projects are rubric-graded
  under Projects.
- **[RULE]** Every assessment is calibrated so that honest work is the
  easiest path to full credit and a student who merely showed up earns a
  passing but mediocre score.
- **[RULE]** Final project: student's choice of topic, must push beyond
  what the course covered. Each unit names at least one pointer toward
  topics the course does not teach.

## Design threads

- **[RULE]** The course's answer to "why learn this when AI writes
  code" is the durable ideas: information and encoding, algorithms,
  decomposition, abstraction. Unit 1 sets that up; the coding units
  echo it without lecturing about it.
- **[DEFAULT]** Applied contexts rotate across math, science, and
  humanities flavors rather than committing to one theme.
- **[DEFAULT]** micro:bits stay in the box unless a concept lands better
  on a device than on a screen.
